# 2026-06-01 师兄视频后续工作规划

本文根据 `C:/Users/123/Desktop/bandicam 2026-06-01 10-51-51-682.mp4` 的视频内容、音频转写和当前项目状态整理。核心判断是：网页端 3D 温度场演示和 “Abaqus/路径 CSV -> JSON -> 前端显示” 链路已经跑通，下一阶段主线应从继续美化前端转向真实传感器接入、实际打磨数据采集、仿真校准和粗糙度预测。

## 总体路线

1. 先把传感器和采集链路弄清楚，能读出真实数据。
2. 再做小规模打磨实验，形成第一批真实力、振动、声发射、主轴状态和粗糙度标签。
3. 然后用真实数据反过来校准 Abaqus 仿真，补齐材料、热源、边界和验证依据。
4. 当仿真与实测差异能控制到可解释范围后，再做仿真数据与实测数据融合。
5. 最后基于真实数据和仿真辅助数据做粗糙度 Ra 预测模型。

## 阶段 1：传感器与采集设备摸底

**时间建议：2-3 天**

目标：明确每个传感器怎么接、输出什么、采样率多少、是否需要标定。

需要确认的设备：

- 六维力传感器 `M3553C`：量程、坐标系、标定矩阵、输出是工程量还是电压/电流。
- 六维力采集卡 `M8229`：实际通信方式是 EtherCAT 还是串口，实际采样率和导出格式。
- 三轴加速度传感器 `CA-YD-3EC3001`：IEPE 供电、灵敏度 `100 mV/g`、安装方向。
- 振动采集器 `YE6275D`：通道配置、采样率、导出文件格式、是否能导出 FFT 或只导出原始波形。
- 声发射设备：型号、采样率、单位、前置放大器、导出格式；当前资料最缺。
- 主轴控制器 `RBZ-E30-B80`：是否读取转速、负载、电流、报警；RS485 Modbus 寄存器地址是否有资料。
- `AI820`：确认它在本系统中是 PAC/控制平台还是直接采集设备，不要把它误写成普通模拟量模块。

交付物：

- 更新 `docs/实验数据字段表.md` 中所有“待确认”项。
- 新增或整理一份设备接线/通信表，至少包含：设备名、接口、采样率、单位、软件、导出格式、负责人。

验收标准：

- 每个传感器都能回答三个问题：接在哪里、读出来是什么量、是否需要换算或标定。
- 如果读出的是电压/电流，必须记录换算公式或标定来源。

## 阶段 2：单设备读数测试

**时间建议：3-5 天**

目标：先不做复杂实验，只验证每个设备能单独读数和保存数据。

任务拆解：

1. 六维力单独读数
   - 空载记录 30-60 秒。
   - 手动轻压/加载记录 30-60 秒。
   - 检查 Fx/Fy/Fz/Mx/My/Mz 是否方向合理、是否有漂移、是否需要清零。

2. 三轴振动单独读数
   - 空载记录 30-60 秒。
   - 主轴空转记录 30-60 秒。
   - 轻微敲击或接触记录 30-60 秒。
   - 检查 RMS、峰值、主频是否随工况变化。

3. 声发射单独读数
   - 先确认设备能采集和导出。
   - 记录空载、接触、轻微摩擦三种状态。
   - 暂时只要求能看到幅值/能量/事件变化，不急着做复杂特征。

4. 主轴状态读数
   - 记录设定转速、实际转速、启停、报警状态。
   - 如果能读负载/电流，同步记录。

交付物：

- 每类传感器至少一份原始文件或导出样例。
- 每类传感器至少一份窗口特征摘要 CSV。
- 更新 `docs/实验数据字段表.md`，用真实导出字段修正草案字段。

验收标准：

- 不是只看软件波形，而是要保存出文件。
- 文件中有时间戳、通道名、单位、采样率或能追溯采样率。
- 能判断每个通道是否可信、是否需要标定。

## 阶段 3：接入当前前端的最小数据链路

**时间建议：3-5 天，可与阶段 2 后半段交叉**

目标：先不要急着做实时 UDP 或数据库，优先把真实导出文件转为前端可回放的 CSV/JSON，让当前网页从随机模拟过渡到真实数据回放。

推荐路线：

- 高频原始波形保留在原始文件中，不直接塞进前端大 JSON。
- 前端第一版只读取窗口级摘要，例如 0.5 s、1 s 或 2 s 一个窗口。
- 每个窗口包含力 RMS、力峰值、振动 RMS、振动主频、声发射能量、主轴转速、数据质量标记。

建议文件：

- `data/demo/sensor_window_features.csv`：第一版真实或半真实窗口特征。
- `public/simulation/sensor_window_features.json`：前端读取的回放 JSON。
- `scripts/convert-sensor-features-csv.js`：CSV 转 JSON 脚本。
- `src/sensor-data.js`：前端解析和校验窗口数据。

前端显示目标：

- 顶部四个指标卡能使用回放数据，而不是纯随机模拟。
- 切削力、振动、声发射、主轴页面能显示同一段实验窗口数据。
- 页面必须标注数据来源：真实采集、设备导出样例、或演示样例。

验收标准：

- 跑 `npm.cmd test` 和 `npm.cmd run build` 通过。
- 前端可以在无网络环境读取本地 JSON。
- 数据缺失时页面有明确提示，不要静默回退成“看似真实”的随机数据。

## 阶段 4：第一批实际打磨实验

**时间建议：1 周**

目标：采集一批可用于后续仿真校准和粗糙度预测的真实数据。第一批实验不要追求工况很多，重点是流程完整。

最小实验设计：

- 工件：先用平板或容易测量的试样，不急着上复杂曲形管道。
- 路径：沿用当前网页中的直线路径口径，便于与温度场和前端演示对应。
- 进给速度：至少固定一个基准值，例如当前 `10 mm/s`。
- 主轴转速：先固定一个基准值。
- 法向接触：尽量记录或控制一个稳定接触载荷。
- 重复次数：每个工况至少 3 次，便于判断波动。

同步采集：

- 六维力。
- 三轴振动。
- 声发射。
- 主轴状态。
- 路径或加工时间段。
- 加工后粗糙度 Ra。

粗糙度测量：

- 每个加工区段记录测点位置。
- 每个位置建议重复测量 3 次。
- 保存测量仪器、方向、取样长度、评价长度等参数。

交付物：

- `data/raw/` 下的原始采集文件。
- `data/features/` 下的窗口特征文件。
- `data/labels/` 下的粗糙度标签文件。
- 一份实验记录表，说明每次实验的工况、文件路径和异常情况。

验收标准：

- 每条 Ra 标签能对应到一个加工区段或一段时间窗口。
- 每次实验的传感器文件能追溯到同一个实验编号。
- 至少能画出力、振动、声发射、主轴状态随时间变化的曲线。

## 阶段 5：仿真模型校准

**时间建议：2-4 周，与实验数据积累并行**

目标：把当前 Abaqus 占位温度边界升级为有依据的热源/接触模型，并用实验数据校准。

需要补齐的参数：

- 工件材料热导率、密度、比热。
- 涂层材料参数。
- 磨头材料或等效接触参数。
- 主轴转速、磨头半径、法向力。
- 摩擦系数或等效热流功率。
- 热分配比例。
- 环境对流换热系数。
- 初始温度和边界温度。

仿真升级顺序：

1. 固定圆形热源：用于检查网格、单位和温度范围。
2. 移动热源：与当前路径 CSV 对齐。
3. 热流边界：替代当前占位温度边界。
4. 热-力接触模型：在前面结果有意义后再做。

验收标准：

- 仿真输出仍能导出 `x_mm,z_mm,temperature_c` 或后续扩展格式。
- 文档能说明每个参数来源：实验、设备设置、手册、文献或假设。
- 与实测温度或间接指标对比后，误差能解释；师兄提到的目标可以先按 15%-20% 作为中期方向。

## 阶段 6：粗糙度预测基线

**时间建议：有第一批真实标签后开始**

目标：先做能解释的简单模型，不急着上复杂深度学习。

输入特征：

- 力：均值、RMS、峰值、峰峰值、接触丢失标记。
- 振动：RMS、峰值因子、主频、频带能量。
- 声发射：能量、RMS、Hits/Counts 或设备可导出的等效特征。
- 主轴：转速偏差、负载、电流、报警状态。
- 工艺参数：转速、进给速度、法向力、磨头编号。
- 仿真辅助量：温度峰值、温度梯度、热影响区宽度。

第一版模型：

- 先用线性回归、随机森林或梯度提升树作为基线。
- 重点看特征重要性、误差范围和数据质量，而不是追求复杂模型。

验收标准：

- 有训练集/测试集划分。
- 有 MAE、RMSE 或相对误差。
- 能说清哪些特征对 Ra 有贡献。
- 如果数据太少，应明确写成“建模流程验证”，不写成可靠预测模型。
