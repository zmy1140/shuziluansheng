# 下一步任务清单

最后更新：2026-06-08

本清单面向科研推进和设计报告沉淀，重点说明“接下来为什么做、做到什么程度、需要什么依据”。工程实现层面的长期待办仍以 `docs/todo.md` 为准。

## P0：立即推进

1. 传感器与采集设备摸底
   - 当前依据：2026-06-01 师兄视频明确要求近期先把传感器接入和数据读取弄清楚。
   - 目标：明确六维力、三轴加速度、声发射、主轴状态分别怎么接、用什么软件读、输出什么单位、采样率多少、是否需要标定。
   - 需确认：M3553C 标定参数、M8229 实际通信方式、YE6275D 实际接线和采样配置、声发射设备资料、主轴 Modbus 寄存器地址、AI820 在系统中的真实职责。
   - 验收：每个设备都能回答“接在哪里、读出来是什么量、是否需要换算或标定”。

2. 单设备读数测试
   - 目标：先不做复杂打磨实验，分别验证六维力、三轴振动、声发射和主轴状态能否单独读数并保存文件。
   - 建议样例：空载 30-60 s、主轴空转 30-60 s、轻微接触/敲击 30-60 s。
   - 验收：每类传感器至少有一份原始文件或导出样例，且能说明通道名、单位、采样率和数据质量。

3. 验证第一版实验数据字段表
   - 状态：已新增 `docs/实验数据字段表.md`，当前为采集归档字段草案，没有真实采集数据。
   - 目标：用真实采集文件或设备导出样例核对字段名、单位、采样率、通道映射、时间同步和 Ra 标签对应关系。
   - 验收：字段表中的关键“待确认”项能根据真实样例修正。

4. 真实数据到前端的最小回放链路
   - 当前状态：YE6275D 三轴加速度已完成第一版真实导出样例回放；静止、轻敲、晃动三组 `_xyz.csv` 已转换为 `public/simulation/acceleration_features.json`，网页振动页可循环显示 1 秒窗口特征。
   - 下一目标：继续把六维力、声发射、主轴状态和 Ra 输入特征也按同样的“原始文件保留 + 窗口特征 JSON 回放”路线接入。
   - 建议路线：高频原始波形保留为原始文件，前端只读取窗口级摘要。
   - 验收：网页能回放多源真实或设备导出样例数据，并明确标注数据来源。

5. 第一批实际打磨实验方案
   - 目标：传感器能读数后，设计小规模实际打磨实验，采集力、振动、声发射、主轴状态和粗糙度 Ra 标签。
   - 建议：先用平板或易测量试样，路径和当前直线演示保持一致，每个工况至少重复 3 次。
   - 验收：每条 Ra 标签能对应到一个加工区段或时间窗口。

6. 仿真校准参数准备
   - 当前状态：已完成 Abaqus 简化温度场和固定圆形热源到前端的链路验证。
   - 下一目标：在真实数据采集并行推进时，继续补齐材料热参数、真实热源功率、摩擦生热比例、接触面积、对流边界和验证方式。
   - 边界：仿真校准是并行任务，但近期不应压过传感器接入和真实数据采集主线。

## P1：近期推进

1. 建立监测信号本地 CSV/JSON 回放样例
   - 状态：路径 CSV 到路径 JSON、温度场 CSV 到温度场 JSON 已完成第一版；力、振动、声发射、主轴和 Ra 的回放尚未完成。
   - 目标：在已完成路径和温度场格式的基础上，继续用结构化文件替代纯随机模拟数据。
   - 前提：优先基于真实设备导出样例选择窗口级摘要字段，不直接把高频原始波形塞进前端大 JSON。
   - 注意：若使用伪真实数据，必须在界面和报告中明确标注。

2. 完善 Abaqus 结果到前端的映射格式
   - 状态：已完成简化厚板 Mises 应力映射原型、温度场 CSV/JSON 第一版格式，以及移动热源温度场 ODB 后处理脚本。
   - 下一步：继续记录不同 Abaqus 输出变量、不同曲面/网格形式如何归一到 `x_mm,z_mm,temperature_c` 或后续扩展字段。
   - 仍需确认：材料热参数、热源模型、接触/摩擦热比例、散热边界、单位、参考温度、最大/最小值和色带范围。

3. 确认真实仿真和实验边界
   - 目标：把“当前简化厚板映射原型”和“未来真实磨抛仿真”的边界写清楚。
   - 需确认：真实工件几何、涂层材料、磨头接触形式、载荷/位移边界、轨迹输入、输出变量和验证数据。

4. 整理第一阶段与第二阶段演示说明
   - 目标：形成可给师兄/导师汇报的说明材料。
   - 内容：当前已完成的前端壳体、3D 加工动画、Abaqus 映射原型，当前均为模拟或链路验证数据，后续如何接真实实验/仿真/预测模型。

5. 持续更新设计报告
   - 目标：每次完成重要设计、仿真、实验、代码或数据处理任务后，同步写入 `docs/design_log.md`，必要时新增阶段性设计报告。
